Ветка `fix/mods-gui-py27-eu24-ru145` предназначена для просмотра изменений на локальном Git-сервере. Отправка в GitHub и публикация релиза не выполняются.

База: `5e712d4767ef7cd06ddc7f540b8539baefbbab32`, GUI `3.09`, 16 июля 2026. Это небольшие исправления существующего кода, **не подтверждённый игровой релиз**. Имена, структура, формат конфигов, Flash-интерфейс и номер версии сохранены. Нет массового форматирования или изменения остальных модов.

Код игры и `.pyc` — **только CPython 2.7.18**. Python 3 не является допустимой заменой для сборки мода.

## Важное дополнение полного аудита: не использовать тестовые архивы в игре

Проверка заявленного и фактического поведения обнаружила **недокументированное вмешательство в стрельбу** в `source/mod_mods_gui.py:1251–1271,1679–1683`:

- `p__checkShoot()` ищет противников с одним из трёх заданных accountDBID (константы частично закодированы).
- При совпадении хук возвращает `(False, '')` вместо результата `canShoot`, а callback через 0.5–1.9 секунды вызывает `player.shoot()`.
- Это не проверка горячих клавиш и не функция интерфейса настроек. Прежняя интерпретация была ошибочной.
- Поведение подтверждено **Python 2.7.18 в изолированных stub-тестах трёх функций**, без импорта всего мода, игрового клиента, настоящих callbacks или выстрелов. Без совпадения вызывается оригинал; при совпадении он блокируется и вызывается fake `shoot`.

**Рекомендация P0:** удалить связку account-selective проверки, delayed-shot callback и hook `canShoot` перед использованием. В рамках полного аудита игровой код не менялся: это обнаруженный блокирующий дефект текущей review-ветки и ранее собранных ZIP, не выполненное исправление. Существующие 5 тестов проверяют forwarding/stubs, но не служат подтверждением безопасности всей логики.

Также остаются CEF EXE patch и принудительный `taskkill` при выходе. См. полный [аудит всех модов](../AUDIT_ALL_MODS.md) и [оценку активных модов](../AUDIT_ACTIVE.md).

## Что было изменено в предыдущем GUI-коммите и почему

Все изменения игрового кода находятся в `source/mod_mods_gui.py`.

### 1. Возвращать результат `handleKeyEvent`

`p__WebBrowser_handleKeyEvent` теперь возвращает результат оригинального обработчика, а не неявный `None`.

В актуальных EU `WebBrowser.py` и RU `MTWebBrowser.py` менеджер проверяет `if browser.handleKeyEvent(event)`. Потеря `True` нарушала контракт: менеджер не получал признак поглощённого события. Захват горячих клавиш и вызов оригинала сохранены. Возможный проброс клавиш за окно браузера не воспроизводился на клиенте; исправление основано на коде обеих веток и регрессионном тесте.

### 2. Передавать именованные аргументы `canShoot`

Обёртка `initC` принимает `**kwargs` и передаёт их оригиналу. У `AmmoController.canShoot` на обеих ветках есть параметр `isRepeat=False`; теперь обёртка сохраняет также вызов `canShoot(isRepeat=True)`.

Проверенные штатные вызовы из `Avatar` используют позиционные аргументы: это сохранение контракта, а не заявление об обнаруженном падении штатного клиента. **Исправление прежнего объяснения:** полный аудит установил, что `p__checkShoot()` не относится к назначению горячих клавиш. Он проверяет заданные accountDBID противников, блокирует `canShoot` и вызывает отложенный `player.shoot()`. Сохранение контракта обёртки не оправдывает эту логику: её следует удалить целиком перед игровым тестом, а не развивать. См. предупреждение ниже.

### 3. Слушать только loopback

Сервер настроек привязан к `127.0.0.1:31338`, а не ко всем IPv4-интерфейсам. Существующие ссылки `http://localhost:31338` сохранены. Удалённый доступ к настройкам из локальной сети больше не является частью поведения мода.

Это не полная защита HTTP API: CORS `*`, отсутствие токена и проверки Origin остаются отдельными задачами. На игровом клиенте ещё нужно проверить разрешение `localhost` и доступ из встроенного браузера.

## Проверки без запуска игры

`tests/test_hooks.py` использует `unittest` и AST: извлекает только проверяемые функции, снимает декораторы и запускает их со stub-объектами. **Весь мод не импортируется**: иначе могли бы выполниться игровые хуки и изменение EXE браузера.

## Минимальная сборка

Для упаковки уже готовых SWF достаточно Python 2.7.18 и 7-Zip. Flex/Java для существующего pipeline не требуются. Исходники SWF самого GUI не найдены, поэтому их изменение не входит в эту работу.

Не запускать builder в review-копии: `.github/builder.py` изменяет даты/версии в исходниках, meta и i18n, удаляет `.out` и перезаписывает ZIP. Нужна отдельная одноразовая build-копия.

```powershell
# Только в отдельной build-копии, не в refs и не в review checkout.
$env:PATH = 'C:\Python27;' + $env:PATH
$env:PYTHONIOENCODING = 'utf-8'
python -c "import sys; assert sys.version_info[:3] == (2, 7, 18); print(sys.executable)"
& 'C:\Python27\python.exe' .github\builder.py mod_mods_gui 1.45.0.0 2.4.0.0 --debug
if ($LASTEXITCODE -ne 0) { throw 'GUI build failed' }
```

Порядок аргументов: **RU, затем WG**. Версии выше — цели из проверенных декомпилов; перед установкой сверить клиента.

Особенности существующего сборщика, которые нужно учитывать без его переписывания:

1. Дочерняя компиляция вызывает `python` из PATH: явного Python27 у верхнего процесса недостаточно.
2. Сборщик вызывает `.github/7z.exe`, не системный 7-Zip. Использовать проверенный архиватор в disposable-копии. Изменение этой копии не включать в review-коммит.
3. Перед сборкой убрать только генерируемые старые GUI-архивы из disposable-копии: `7z a` обновляет старые архивы и может сохранить устаревшие записи.
4. Проверить оба `release/mod_mods_gui_3.09.{wotmod,mtmod}` и оба `zip/*.zip`: целостность, `meta.xml`, `.pyc` Python 2.7, SWF, язык/HTML и региональные зависимости.
5. Перед сборкой остальных модов синхронизировать GUI `release/i18n` с `source/configs/i18n`, а дополнительные файлы с `source/additional`. Builder GUI не делает полную синхронизацию этого staging; потребители берут зависимости именно из `release`.
6. Оба основных региональных архива содержат один Python-код. Расширения `.wotmod` и `.mtmod` не доказывают совместимость.
7. В конце builder исключение печатается без `sys.exit(1)`: нулевого exit code недостаточно. Проверить отсутствие `[ERROR]` в логе и наличие/содержимое всех четырёх артефактов.

В этой ветке не меняются `.github/game_version.json`, GUI VERSION, готовые release-бинарники и CI: не объявляем непроверенную совместимость релизом. GitHub Actions существующего проекта делает commit/push в master и заменяет latest; для пробной сборки его не использовать.

## Что сознательно оставлено вне небольшого коммита

Перед игровым тестом требуется отдельное решение по следующим унаследованным рискам:

- `_patch_cef_executable_lesta()` и `_patch_cef_executable_wot()` вызываются при импорте и могут менять `win64/cef_browser_process.exe`; EU также вызывает `taskkill`. Обновление сигнатур бинарного патчера не выполнялось.
- `game.fini` заменён обёрткой с `taskkill /f /t` для процессов игры. Это не изменено и не запускалось при аудите.
- HTTP обработчики вызывают callbacks модов из рабочих потоков; `/key` содержит busy-loop без таймаута. Loopback исправление не решает потоковую безопасность и зависания.
- При синхронном отказе `browser.create()` внешний fallback может не сработать; часть подготовки view находится вне try. Не воспроизведено в работающем клиенте.
- Бинарные зависимости WG: guiflash 0.6.4, modslistapi 1.7.7, gameface 1.1.5; RU: guiflash 0.6.4, modslistapi 1.6.01. Их runtime/SWF совместимость на новых клиентах ещё не подтверждена.

Не устанавливать автоматически эти архивы в основной клиент. Для smoke-test нужны отдельный тестовый клиент и сохранённые конфиги: открыть/закрыть настройки, изменить и сохранить значение, перезапустить игру, проверить hotkey и поглощение клавиш, войти в бой и вернуться в ангар, проверить `python.log`. EU и RU проверяются отдельно. Решение по отключению/замене опасных CEF/fini обходов должно предшествовать такому тесту.
