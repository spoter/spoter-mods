## Главное: общий GUI нельзя выпускать в текущем виде

В `mod_mods_gui/source/mod_mods_gui.py:1251–1271,1679–1683` обнаружено **недокументированное вмешательство в стрельбу**:

1. По трём заданным accountDBID выбираются противники.
2. `p__checkShoot()` заставляет обёртку `canShoot` вернуть `(False, '')`.
3. Через случайную задержку **0.5–1.9 секунды** callback вызывает `player.shoot()`.

Это не настройка клавиш и не функциональность интерфейса предпочтений. **Прежнее объяснение этой проверки как захвата hotkey было ошибочным и исправлено в UPDATE_NOTES.** Поведение подтверждено отдельным AST/stub-тестом на Python2.7.18: без совпадения вызывается оригинал; при совпадении он блокируется, затем вызывается fake `shoot`. Реальный движок и аккаунты не использовались, численные ID не публикуются.

**P0: удалить весь этот механизм перед игровым тестом, не улучшать его.** Все девять остальных активных модов импортируют GUI и наследуют риск. Предыдущие успешно собранные `mod_mods_gui.zip` / `_RU.zip` содержат эту логику и **не должны использоваться до исправления и повторной сборки**. Пять прежних тестов проверяли forwarding, return и loopback на заглушках, но не смысл реального предиката — их успех не равен проверке безопасности мода.

Также до выпуска нужно исключить или отдельно безопасно заменить автоматическое изменение CEF EXE и `taskkill` в `game.fini`. Для минимальной актуализации правильнее сузить GUI до настроек/интерфейса, а не сохранять вмешательство в стрельбу и исполняемые файлы клиента.

## Ошибки ресурсов и упаковки, которые важно не переоценить

1. `mod_server_turret_extended/source/VERSION:5` требует `configs/serverTurretExtended.json`, фактически есть `configs/mod_server_turret_extended.json`. Сборщик молча пропускает отсутствующий config; это дефект комплектности, не доказанное падение при defaults.
2. `.deprecated/mod_modPackInformer/source/VERSION` требует отсутствующий `configs/i18n`. Проверить реальную необходимость локализации и исправить манифест, а не создавать фиктивные файлы.
3. У tooltip `i18n: ""` в VERSION приводит к копированию файлов source в `mods/configs/spoter/i18n`. В старых ZIP там `.py`, `meta.xml`, YAML; **правильный модовый `.pyc` внутри WOTMOD тоже есть**. Проблема — лишние/ошибочно расположенные файлы, не отсутствие загрузки всего мода.
4. Bookmarks: trailing commas в конце списков (source + ZIP); spotted 6.02: отсутствует запятая после version в ZIP. Четыре crew/vehicle_exp JSON с комментариями успешно разобраны их собственными извлечёнными `json_comments` под 2.7.18: это не те же ошибки.
5. Три archive-only папки имеют реальные пакеты: `mod_dir_indicator_extended` — **testDir 1.04**, `mod_spotDetails` — **spotDetails 1.01**, `mod_spotted_extended` — **spotted 6.02 + spotEngine 1.04**. Их внешних `.py` нет, часть/вся полезная семантика скрыта защитной оболочкой. Нужен исходник или конкретное описание требуемой небольшой функции; восстановление «по названию» не предлагается.
6. Девять `.old` — старые Flex config XML, не забытые Python-моды. Есть AS3-проекты, 25 SWC и абсолютные пути прежнего стенда; их наличие не даёт воспроизводимой Flash-сборки на dev-win11.
7. Старые ZIP несут собственные древние версии GUI/guiflash/modslistapi. Их нельзя устанавливать поверх нового общего GUI или просто переименовать папку версии. Нужна одна выбранная версия зависимости на итоговый комплект.

## Более правильный общий подход без массового переписывания

Следующие пункты — **рекомендации для будущих небольших коммитов**, не проведённый рефакторинг.

### 1. Сначала убрать лишние полномочия из общего GUI

Оставить регистрацию настроек, чтение/сохранение конфигов, UI и обычные hotkey-события. Не должно быть скрытых account checks, стрельбы, правки EXE или завершения чужих процессов. Этот шаг полезнее перехода на новый frontend и относится сразу ко всем девяти потребителям.

Сохранить авторские имена `g_gui`, `inject`, структуру конфигов и работу существующих модов. Менять только подтверждённые контракты; не делать массовое форматирование или перевод на Python3.

### 2. Разделить логику функции и адаптер игры

Для расходников/опыта/кредитов/отметок выделить небольшие чистые функции на Python2.7.18 и пару явных адаптеров EU/RU там, где действительно расходятся типы/сигнатуры. Не нужен новый большой framework. Сравнение по строке локализованного названия игры — хрупкая эвристика; лучше явный target build и проверка нужных возможностей.

Примеры тестов: выбранный расходник; одно/несколько повреждений; отсутствующий cache/result; расход снарядов/премиум-флаги; нулевые/неполные данные; дата миграции конфига. Не требовать BigWorld для такой математики.

### 3. Использовать события и контролируемый lifecycle

Предпочитать существующие события изменения машины/оборудования/результата вместо постоянного перебора всех объектов и запуска потока на каждое сообщение. Если нужен callback — хранить его ID, делать start идемпотентным, отменять на stop и проверять arena/session.

HTTP/сетевые рабочие потоки должны передавать только данные в очередь. Применение настроек и вызов game API — на основном потоке через небольшой контролируемый обработчик, запущенный самим игровым потоком. Убрать busy-loop ожидания клавиши. Не предполагать потокобезопасность BigWorld по одному наличию API.

### 4. UI менять только при доказанной необходимости

Для текста, переключателя, счётчика и небольшой панели сначала сохранить существующий проверенный UI или использовать штатную точку расширения конкретного клиента. Полный перенос всего на Gameface/новый native overlay — не минимальная актуализация и не универсальный ответ.

Для GUI временный внешний браузер может убрать необходимость патчить CEF, но это не автоматически полноценная замена захвата горячих клавиш: ввод и фокус надо проектировать отдельно. Для старого экипажа/ангара сначала решить, какую информацию пользователь реально хочет добавить поверх штатной, затем переносить только её.

### 5. Отличать измерение от прогноза

CreditCalc, marks, blocked-damage, spotting и «бои до опыта» должны явно обозначать оценку и источник данных. Клиентская эвристика не является серверной истиной. Сравнивать с фактическим результатом боя, учитывать регион/режим и не показывать уверенный результат при неизвестных полях.

### 6. Сборка должна проверять комплектность, а не только выдавать ZIP

- Закрепить **Python2.7.18**, доверенный 7-Zip и входные SHA; собирать в одноразовом staging.
- Превратить отсутствующий обязательный source/config/resource в ошибку, а не silent skip.
- Очистка только генерируемых архивов staging, без git reset/clean пользовательских копий.
- Один свежий staging GUI для зависимых модов, без старых версий рядом.
- Проверять manifest/CRC/PYC/региональные расширения и минимальные регрессионные тесты; не считать exit 0 достаточным, текущий builder перехватывает исключение без ненулевого exit.
- Сначала непубликующая локальная сборка. Старый GitHub CI делает commit/push и меняет latest, для этой работы он не нужен.

## Приоритетный план

**P0 — до любой установки общего набора:**

1. Удалить недокументированное управление выстрелами из GUI; исключить CEF EXE patch и forced taskkill либо согласовать безопасную замену.
2. Дополнить тесты отсутствием неразрешённых побочных действий; пересобрать только GUI. Устаревшие тестовые ZIP не использовать.
3. Отдельно исключить текущий Windows tracer из установки, особенно RU; не использовать невалидный extensionless Potapov как зависимость.

**P1 — максимальная польза при малом diff:**

1. Hello как независимый smoke-test загрузки; затем очищенный GUI.
2. `autoServerSight`, `muteSoundHotKey`, `spotted_extended_light` — ключевые API найдены, проверка коротких сценариев и lifecycle.
3. Точечная матрица расходников `repair_extended`, согласование server-turret config; функциональность движения/углов не включать без отдельной оценки.
4. В боевых credit/marks сначала проверить правильность оценок и вывод основной панели, не подключать автоматически старые addons.

**P2 — только выбранные функции:**

- Узкие deprecated-кандидаты: battleChatSwitcher, при потребности artyCrosshair и небольшой tooltip-поднабор. Наличие штатного аналога сначала проверить в конкретном клиенте, не объявлять заранее.
- Объединять дубли по смыслу: bookmarks/globalmap; две реализации crew; близкие spotting-индикаторы. Сохранить одну выбранную реализацию, не ставить все исторические номера вместе.
- Незавершённый ангар creditCalc и marks addons — самостоятельные задачи, а не обязательное условие работы боевой панели.

**P3 / сначала решение о необходимости:**

- Account manager — актуальный механизм входа и безопасность хранения; не перенос старого password-based UI вслепую.
- Informer/stream — нужен живой поддерживаемый канал данных; иначе отключённая сеть и отсутствие отдельного продукта лучше.
- Старые большие angar/crew/quests/SteelHunter реализации — часто дешевле сохранить одну необходимую функцию, чем восстановить всю архитектуру.
- Непрозрачные binaries — запросить пригодный исходник/актуальную доверенную сборку или выбрать маленький открытый аналог по конкретному требованию; совместимость не угадывать.

S/M/L в поимённых отчётах — относительный объём, **не гарантированные часы**. Оценку сроков можно уточнять после выбора нужных функций и появления тестовых клиентов, а не по числу строк Python.

## Правила игры и достоверность заявлений

Публичный Python API не делает любую механику автоматически допустимой. Для autoaim, автоматических consumables/upgrades, вражеских tracers, управляющих выстрелами hooks и отображения необычных данных нужен отдельный региональный review.

- [Официальное обновление Fair Play EU, январь 2026](https://worldoftanks.eu/en/news/general-news/ban-wave-jan-2026/) прямо обсуждает автоматическую блокировку/разрешение firing input и SafeShot, с окончанием переходного периода до 2.2. Это дополнительный риск для обнаруженной логики GUI на цели 2.4, **не заявление о доказанном бане конкретного пакета**.
- [Категории запрещённых модификаций EU](https://worldoftanks.eu/en/content/guide/fair-play/prohibited-mods/).
- [Категории RU](https://tanki.su/ru/content/guide/ban/nonusefulmods/) отдельно упоминают изменение трассеров САУ/вычисление их позиции. Конкретный перечень функций перед выпуском сверять с полными актуальными правилами и при неоднозначности с поддержкой сервиса.

Большие guide-страницы в web-fetch частично обрезались навигацией; детальная сверка всех категорий каждого мода здесь **не объявляется завершённой**. Полная январская публикация EU о firing input была получена. Ни один мод не объявляется запрещённым лишь из-за названия, возраста или имени ZIP `cheat`.

## Что остаётся непроверенным на стенде

- Установленные полноценные клиенты EU/RU не подтверждены, `python.log` после загрузки комплекта и игровые сценарии отсутствуют. Машина — Hyper-V VM с Hyper-V Video; пригодность renderer для такого теста не подтверждена.
- Полная совместимость SWF/моделей/шейдеров с клиентом, восстановленная семантика protected payload, серверная точность расчётов и допустимость каждой спорной механики.
- В Gitea доступен `b4it/wot-src`; подходящий `spoter-mods` репозиторий не найден, создание получает HTTP403 имеющимся токеном. Это не обходили, пользовательский код в чужой репозиторий не отправляли. Review-ветка сохраняется на dev-win11 и аналитической машине; GitHub push отключён.

**Итог:** обновлять следует не «всё до нового номера папки», а выбранные полезные функции. Общий GUI сначала нужно сделать соответствующим своему назначению, затем минимально адаптировать потребителей. По каждому из 43 модов коллекции и 3 дополнительных реализаций приведены самостоятельные оценки заявлений, фактической реализации, улучшений и альтернатив; границы доказанности явно обозначены.
